# カスタムマッチのチーム分け（Teams タブ）企画・設計書

カスタムマッチのロビーに**プレイヤーとして入っている**メンバーを League Client から読み取り、**ランク**と**得意レーン**、**手動の設定（レーン固定など）**をもとに、バランスのよいチーム分けとレーン割り当てを提案する。結果は **Discord にそのまま貼れる文字列**でコピーできる。

- 状態: **企画（未実装）**。§10 の「持ち主に決めてほしいこと」を待つ。
- 決定番号は M-038 を予定（§11 は原案。decisions.md には未記入）。
- 前提として読むもの: [new-app-design.md](./new-app-design.md)（画面構成、MatchState と Workspace）、`next/CLAUDE.md`（ゾーン。`packages/lcu` は 🔴）。
- 作成: 2026-11-27。

---

## 1. 結論（先に要点）

| 論点 | 案 |
|---|---|
| 置き場所 | Top bar に新しいタブ **Teams** を足す（`Viewers / Live Game / Teams / Settings`）。最初は Feature Flag `teamBalancer`（既定オフ） |
| メンバー | LCU の `/lol-lobby/v2/lobby` を GET＋購読し、カスタムロビーの **Team 1 / Team 2 にいる人だけ**を対象にする。観戦枠とボットは除く |
| ランク | LCU の `/lol-ranked/v1/ranked-stats/{puuid}`。ソロ/デュオ → フレックス → 前シーズン → 未設定（手動入力）の順に使う |
| 得意レーン | **第一候補は LCU の戦績**（`/lol-match-history/...` の直近の試合のレーン）。API キー不要・外部送信なし。OP.GG は自動取得には使わず、**「OP.GG で見る」ボタン**（マルチサーチをアプリ内か既定ブラウザで開く）にする（§3.3） |
| 手動の設定 | プレイヤーごとに **レーン固定**・**得意レーン（上書き）**・**NG レーン**・**ランクの上書き**を設定できる。PUUID に紐づけて保存し、次回のカスタムでも効く |
| 分け方 | 10 人なら全通り（チームの組み 126 通り × 各チームのレーン 120 通り）を総当たりしても一瞬。ランク差・レーンの合い具合・対面のランク差を点数にして、**上位 3 案**を出す。「別の案」で近い点数の案を出し直す |
| Discord | 「Copy for Discord」で Markdown の文字列をクリップボードへ。コードブロック版（列が揃う）と絵文字版を選べる |
| 安全面 | LCU は **GET だけ**（書き込みはしない。自動でチームを動かしたりしない）。データは外部に送らない。`packages/lcu` の許可パスの追加は 🔴（人間のレビュー） |
| 確かめられないこと | 実際のカスタムロビーの JSON の形、他人の戦績が LCU で取れる範囲、Riot のポリシー原文（自動取得できなかった）。**Windows 実機で確認が必要**（§9） |

## 2. やること / やらないこと

### 2.1 やること（第 1 段階＝MVP）
- Teams タブ。カスタムロビーにいる間、プレイヤーの一覧（Riot ID、ランク、得意レーン、手動設定）を出す。
- プレイヤーごとの手動設定（レーン固定 / 得意レーン / NG レーン / ランク上書き）。保存して次回も使う。
- チーム分けの提案（上位 3 案、「別の案」、手動で 2 人を入れ替え）。
- Discord 用のコピー。
- ロビーにいないとき・カスタム以外のロビーのときは「カスタムロビーに入ると表示されます」と出す。手動でプレイヤーを足す欄も置く（ロビー外でも使える）。

### 2.2 第 2 段階
- 戦績からの得意レーンの自動推定（§3.3 の方式 A）。
- 「OP.GG で見る」（マルチサーチ）。
- 「この 2 人は同じチーム / 別のチーム」の指定。

### 2.3 やらないこと（範囲外）
- LCU への書き込み（チームの移動、招待、キック、チャットへの自動投稿）。`packages/lcu` に書き込み系を足さない規則（CLAUDE.md）に沿う。
- OP.GG などのページの HTML を読み取ること（スクレイピング）。外部ビューに preload を渡さない規則にも反する。
- 隠れ MMR の推定や、公開されていない値の表示。
- Discord への自動投稿（Bot / Webhook）。コピーして貼るのは人がやる。

## 3. 調査結果

### 3.1 ロビーのメンバー
- `GET /lol-lobby/v2/lobby`（購読は `OnJsonApiEvent_lol-lobby_v2_lobby`）。カスタムロビーでは `gameConfig.isCustom` が true、`gameConfig.customTeam100` / `customTeam200` / `customSpectators` に各枠のメンバーが入る**とされる**（コミュニティの資料による。公式の文書はない。実機で JSON を記録して確かめる → §9）。
- プレイヤー = `customTeam100` ＋ `customTeam200`。観戦（`customSpectators`）とボット（PUUID が無い / `isBot`）は除く。
- 名前は各メンバーの `gameName` / `tagLine` か、無ければ `GET /lol-summoner/v2/summoners/puuid/{puuid}` で取る。

### 3.2 ランク
- `GET /lol-ranked/v1/ranked-stats/{puuid}` で他人のランクも取れる（クライアントのプロフィール画面と同じ情報）。`queueMap.RANKED_SOLO_5x5` の `tier` / `division` / `leaguePoints` を使う。
- 使う順: ソロ/デュオ → フレックス → 前シーズンの最終ランク → どれも無ければ「Unranked」（既定値で計算し、手動で直せる）。
- 点数化（案）: Iron IV = 0、1 ディビジョン = 100 点、LP を足す。Master 以上は Diamond I の上に LP をそのまま足す。

| ランク | 点（IV の 0LP） |
|---|---|
| Iron | 0 |
| Bronze | 400 |
| Silver | 800 |
| Gold | 1200 |
| Platinum | 1600 |
| Emerald | 2000 |
| Diamond | 2400 |
| Master+ | 2800 ＋ LP |

### 3.3 得意レーンの取り方

| 方式 | 中身 | キー | 安定性・ルール面 | 評価 |
|---|---|---|---|---|
| **A. LCU の戦績** | `GET /lol-match-history/v1/products/lol/{puuid}/matches?begIndex=0&endIndex=49` の各試合のレーン/ロール（`timeline.lane` と `role`）を数える。ランク戦・ノーマル（ドラフト）だけ数え、ARAM・カスタムは除く | 不要 | クライアントが表示している情報。外部に何も送らない。ただし旧形式のフィールドでサポート/ADC の判定が粗い。他人の戦績がどこまで取れるかは実機で確認（§9） | **採用（第 2 段階）** |
| B. Riot 公式 API（match-v5） | `teamPosition` がきれいに取れる | **必要** | 配布アプリにキーを埋め込めない。開発キーは 24 時間で切れる。各自にキーを取らせるのは手間 | 採用しない（将来、ユーザーが自分のキーを入れる上級設定にする余地はある） |
| C. OP.GG | 公開の REST API は無い。AI エージェント向けの公式 MCP サーバー（`mcp-api.op.gg`、`lol-summoner-search` など）はあるが、アプリから呼ぶ用途・規約は不明。HTML の読み取りは規約と安定性の面で不可 | — | 仕様変更で壊れやすい。規約が不明 | **自動取得には使わない**。代わりに**マルチサーチをアプリ内のビューアか既定ブラウザで開くボタン**を置き、人が目で確かめる |
| D. 手動 | ユーザーが得意レーン・固定レーンを入れる | 不要 | 確実 | **採用（第 1 段階）**。A の結果より手動が優先 |

得意レーンの決め方（方式 A）: 直近の対象試合でのレーン別の割合を出し、割合の高い順に「メイン」「サブ」とする。試合数が 5 未満なら「データ少」と表示し、レーンの点数を弱める。

### 3.4 手動の設定（プレイヤーごと、PUUID に紐づけて保存）

| 設定 | 意味 | 分け方での扱い |
|---|---|---|
| レーン固定 | 「この人は必ず JG」 | **必ず守る**（守れない組み合わせは出さない）。同じチームで同じレーンの固定が 2 人いたら、別チームに分ける。3 人以上なら警告を出す |
| 得意レーン | メイン / サブを手で決める | 自動推定より優先 |
| NG レーン | 「SUP はやらない」 | 強いペナルティ（全員を満たせないときだけ破る。破ったら案に ⚠ を付ける） |
| ランク上書き | 未ランク・サブ垢・久しぶりの人 | 取得したランクの代わりに使う |
| 参加しない | ロビーにいるが今回は数えない | 対象から外す |

保存先は既存の settings と同じ仕組み（`packages/core/src/settings.ts` の zod スキーマに `teamBalancer.players: Record<puuid, {...}>` を足す）。名前は表示用に最後に見た Riot ID も持つ。

## 4. 分け方（アルゴリズム）

10 人の場合:
1. チームの組み: 10 人から 5 人を選ぶ 252 通り ÷ 2（青赤の入れ替えは同じ）= 126 通り。
2. 各チームのレーン割り当て: 5! = 120 通り。チームごとに独立に最良を選べるので、計算は 252 × 120 ≒ 3 万回。総当たりで数ミリ秒。
3. 点数（小さいほどよい）:
   - `ランク差` = |青の合計点 − 赤の合計点|
   - `レーン適性` = 各人に「固定 0 / メイン 0 / サブ 小 / その他 中 / NG 大」のペナルティを足す
   - `対面差` = 各レーンの対面同士のランク点の差の合計（1 レーンだけ大差になるのを防ぐ）
   - `合計 = w1 × ランク差 + w2 × レーン適性 + w3 × 対面差`。重みは Settings で「ランク重視 ↔ レーン重視」のスライダー 1 本にまとめる
4. 点数の良い順に上位 3 案を出す。「別の案」を押すと、最良から一定の幅に入る案から順に出す（毎回同じ人と組まないように）。

人数が 10 人でないとき:
- 偶数（6・8 人）: チーム分けだけ行い、レーンは「得意レーンの一覧」として出す（3v3・4v4 はレーンの意味が薄いため）。
- 奇数: 「1 人が観戦 / 交代」になる案として、誰を外すかも選ばせる（第 2 段階）。

この計算は `packages/core` の純粋な関数（`balanceTeams(players, options) => Proposal[]`）にして、テストで固める。

## 6. Discord へのコピー

「Copy for Discord」でクリップボードに入れる。形式は 2 種類（最後に選んだ方を覚える）。

**コードブロック版**（等幅で列が揃う。既定）
````
**チーム分け案 1**（ランク差 10 / 平均 Gold II）
```
🟦 BLUE (avg G2)          🟥 RED (avg G2)
TOP  Alice   P4          TOP  Frank   G1
JG   Bob     G2          JG   Grace   P4
MID  Carol   S1          MID  Heidi   G3
BOT  Dave    G1          BOT  Ivan    G2
SUP  Erin    G4          SUP  Judy    S2
```
````

**絵文字版**（スマホでも崩れにくい）
```
🟦 **BLUE**（平均 Gold II）
TOP Alice / JG Bob / MID Carol / BOT Dave / SUP Erin
🟥 **RED**（平均 Gold II）
TOP Frank / JG Grace / MID Heidi / BOT Ivan / SUP Judy
```
- オプション: ランクを載せる / 載せない、`#タグ` を載せる / 載せない。
- Discord のメッセージ上限（2000 文字）を超えないことをテストで確かめる。
- 全角文字の名前は等幅でも幅がずれるので、コードブロック版は表示幅（全角 = 2）で揃える。

## 8. テスト
- core: ランクの点数化、レーン推定、固定・NG の制約、10 / 8 / 6 人、固定の衝突、Discord 文字列（スナップショットと 2000 文字の上限、全角の幅）。
- hub: 合成のロビーイベントから、観戦とボットが除かれること。
- web: Teams ページの stories（ロビーなし / 取得中 / 10 人 / 警告あり）と Storybook の E2E、スクショを目で確認。
- Electron の E2E: fake-lcu のカスタムロビーで Teams に 10 人出て、コピーできること。

## 9. 実機でしか確かめられないこと（Windows + 本物の LoL）
- カスタムロビーの `/lol-lobby/v2/lobby` の実際の形（`customTeam100` などの名前、観戦枠、ボットの表し方）。記録ツールで伏せて scenarios に入れる。
- 他人の `ranked-stats` と `match-history` が LCU で取れるか、何試合分取れるか、取得の速さ（10 人分）。
- **Riot の開発者ポリシーの原文**（ページが自動取得できず未確認）。検索結果の要約では「カスタムキューの戦績は、本人の同意なく公開表示してはいけない」という趣旨の規定がある。本機能はカスタムの戦績は使わず（ランク戦・ノーマルだけ数える）、外部にも公開しないが、人間が原文を確認する。
- OP.GG マルチサーチの URL の形（地域、Riot ID の書き方）。

## 10. 持ち主に決めてほしいこと
1. タブの名前: `Teams`（案）/ `Custom` / その他。
2. 未ランクの人の既定ランク: 計算から外して手動入力を促す（案）/ Silver など固定値。
3. 第 1 段階で戦績からの自動推定まで入れるか、手動設定＋ランクだけで先に出すか（案: 先に出す）。
4. 重み（ランク差とレーンの合い具合）の既定: 半々（案）。
5. 10 人以外（6・8 人）に対応するか（案: チーム分けだけ対応）。
6. Discord の既定の形式: コードブロック版（案）/ 絵文字版。
7. OP.GG のボタン: アプリ内のビューアで開く / 既定ブラウザで開く（案: 既定ブラウザ。外部ビューの許可ホストを増やさずに済む）。

## 11. 決定: M-038（原案）

## M-038 カスタムマッチのチーム分け（Teams タブ、Feature Flag、2026-11-27）
- Teams タブを足し、カスタムロビーのプレイヤー（観戦・ボットを除く）をランクと得意レーンと手動設定からチーム分けし、上位 3 案を出す。Discord 用の文字列をコピーできる。Feature Flag `teamBalancer`（既定オフ）。
- データは LCU の GET だけ（ロビー、ランク、戦績）。LCU への書き込み、外部サイトの HTML の読み取り、外部への送信はしない。OP.GG は人が見るためのリンクにとどめる。
- 手動のレーン固定は必ず守る。NG レーンは全員を満たせないときだけ破り、⚠ を付ける。
